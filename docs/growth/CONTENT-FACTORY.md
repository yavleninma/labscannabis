# Контент-завод: контракт генератора

Дата: 2026-08-28. Ветка каркаса: `claude/seo-strategy-site-0i81vy`.

Этот документ читает человек, которому через полгода поручили «добавить ещё
страниц». Здесь написано, что такое кластер, куда класть данные, как машина
решает, пускать ли страницу в индекс, и почему CI краснеет.

---

## 1. Зачем вообще ворота, если можно просто сгенерировать страницы

Выгрузка Google Search Console по домену: **149 URL в статусе «Обнаружена, не
проиндексирована»**. Это не «Google не дошёл». Это Google посмотрел на массовые
шаблонные страницы этого сайта и **отказался** их индексировать.

Из этого следует ровно один вывод, и он определяет всю конструкцию ниже:

> Генерация страницы и допуск страницы в индекс — **разные события**.
> Первое делает генератор. Второе делает проверка.

Завод, у которого нет ОТК, добавляет к этим 149 столько URL, сколько ему
запустят, и не добавляет трафика. Поэтому здесь страница **всегда собирается**
(у неё есть URL, её видит посетитель, по ней ходит краулер), но получает
`<meta name="robots" content="index, follow">`, попадает в `sitemap.xml`,
получает `hreflang` и JSON-LD **только если прошла ворота качества**.

Не прошла — остаётся живой страницей под `noindex, follow`. Не 404, не
редирект: ссылки на неё могут уже существовать.

## 2. Карта: что где лежит

| Файл | Что делает |
| --- | --- |
| `scripts/lib/quality-gate.mjs` | **Ворота.** Пороги и функция `evaluateCandidates()`. Чистый модуль: ничего не читает с диска и ничего не пишет. |
| `src/content-factory/registry.mjs` | Реестр кластеров. Прогоняет ворота во время сборки и отдаёт готовый список допущенных слагов. |
| `src/content-factory/clusters/*.mjs` | Кластеры. Один файл — один кластер. Образец: `strains.mjs`; второй — `questions.mjs` (состав вопросов у каждой локали свой); третий — `geo-routes.mjs` (маршрут от ориентира; расстояние вычисляется гаверсинусом, а фактура маршрута лежит в `src/data/landmarks.ts`). |
| `src/lib/index-policy.mjs` | Единый allowlist = ручные страницы-личности **+** то, что пропустили ворота. |
| `scripts/check-seo.mjs` | Вторая ступень ОТК: те же ворота, но по отрисованному `dist/`. |
| `scripts/check-factory.mjs` | `npm run check:factory` — отчёт ворот без сборки. |

Поток данных, в одну сторону и без обратных связей:

```
кластер (текст страниц)
      │
      ▼
scripts/lib/quality-gate.mjs        ← пороги
      │  вердикт: index / noindex
      ▼
src/content-factory/registry.mjs
      │
      ▼
src/lib/index-policy.mjs  ──┬──► PageLayout.astro     → <meta name="robots">
                            ├──► astro.config.mjs     → фильтр sitemap
                            ├──► footer-seo-links.ts  → перелинковка
                            └──► check-seo.mjs        → проверки
```

**Вердикт нигде не хранится.** Он вычисляется заново при каждом импорте
реестра. Так сделано по двум причинам: (1) сборке запрещено писать в рабочее
дерево — CI делает `git diff --exit-code`; (2) закоммиченный allowlist
разошёлся бы с текстом страниц при первой же правке копирайта, и мы вернулись
бы к ручному списку, только хуже — к ручному списку, который выглядит
автоматическим.

## 3. Что такое кластер

Кластер — это семейство страниц, у которых **общий шаблон и разные данные**.
Три страницы сортов — кластер. Четыре гео-маршрута — кластер. Главная —
не кластер, это страница-личность.

Кластер объявляет пять вещей (`src/content-factory/clusters/strains.mjs`):

```js
export const STRAINS_CLUSTER = {
  id: "strains",                 // машинное имя, попадает в отчёты
  hubSuffix: "strains",          // хаб кластера — он ведётся вручную
  linkLabelKeys: { ... },        // слаг → ключ подписи в src/i18n/<locale>/ui.json
  related:       { ... },        // слаг → смысловые соседи
  candidates() { return [ ... ]; },
};
```

`candidates()` возвращает плоский список «слаг × локаль»:

```js
{
  clusterId: "strains",
  locale: "en",
  suffix: "strains/white-widow",   // без локали и без слэшей по краям
  title:  "…",                     // то, что уедет в <title>
  h1:     "…",
  text:   "…",                     // СОБСТВЕННЫЙ текст страницы
}
```

### Что такое «собственный текст»

Всё, что шаблон отрисует внутри `<main>`/`<article>`, и **ничего** из общего
обвеса: ни шапки, ни футера, ни контактной панели, ни sticky-CTA, ни блока
соседних ссылок. Ровно то, что `extractMainText()` из
`scripts/lib/text-similarity.mjs` вырежет из готового HTML.

Это не формальность. Если собрать `text` не так, как рисует шаблон, ворота
будут мерить одну страницу, а на прод уедет другая, и вторая ступень ОТК это
поймает — но уже красной сборкой, а не понятным сообщением.

Смотри `ownText()` в `clusters/strains.mjs`: там поля перечислены в том же
порядке, в каком их выводит `src/components/StrainArticle.astro`.

### Формат файла данных

Данные кластера читают **и Vite (сборка), и голый Node** (`check:seo`,
`check:factory`). Отсюда жёсткое требование:

- модуль кластера — **`.mjs`**;
- копирайт можно держать в `.ts` (как `src/data/strain-pages.ts`), но тогда
  он импортируется **по полному имени с расширением** (`"../../data/strain-pages.ts"`)
  и обязан быть **стираемым TypeScript**: только `import type`, `interface`,
  `type` и аннотации. Никаких `enum`, `namespace`, декораторов и никаких
  алиасов `@/` в значимых (не-типовых) импортах — Node их не резолвит;
- никаких `fs`, `fetch` и обращений к сети в момент импорта. Данные лежат в
  репозитории, иначе сборка перестаёт быть воспроизводимой.

## 4. Ворота: что именно проверяется

Все пороги — в `scripts/lib/quality-gate.mjs`, каждый с комментарием, откуда
взято число. Кратко:

| Проверка | Порог | Откуда число |
| --- | --- | --- |
| Объём собственного текста (en, ru, ar) | **≥ 640 слов** | p05 объёма по ВСЕМУ indexable-набору `dist/` (n=127: min 518, p05 644, медиана 873), округлённый вниз до десятков. Прежние 400 пришли из требования владельца и к сайту отношения не имели: самый тонкий кандидат нёс 646 слов, то есть порог был вдвое ниже фактического пола и связывающим быть не мог. |
| Объём собственного текста (th / zh / ko / ja) | **2500 / 1050 / 1300 / 1450 символов** | То же правило, в символах: p05 по indexable-набору локали (n=15 на локаль — th min 2168 / p05 2505, zh 1042 / 1059, ko 1237 / 1307, ja 1381 / 1460), округлённый вниз до полусотни. Прежние значения считались через переводной коэффициент от тех же 400 слов и оказывались втрое-вчетверо ниже фактического пола. |
| Похожесть с уже допущенной страницей той же локали | **Жаккар ≤ 0.20** | Прежние 0.35 были откалиброваны по дорвейной гео-сетке (пары 0.81–0.82), удалённой в том же раунде, — то есть по популяции, которой на сайте больше нет. По нынешнему корпусу: максимум попарной похожести среди indexable 0.16 (th, две написанные руками страницы), у заводских кандидатов против всего корпуса локали 0.06. |
| Заимствование (доля своих шинглов, стоящих на indexable-страницах локали — по ОБЪЕДИНЕНИЮ) | **≤ 55 %** | Отдельная метрика, потому что Жаккар разводится объёмом: страница «наполовину скопирована, наполовину дописана» даёт 0.33 и проходит. Попарная версия обходилась в один приём: сшивка из ТРЁХ indexable-страниц по трети от каждой (ни одного своего слова) давала Жаккар 0.23 и попарное включение 38 % — оба под порогом. Считается объединение, поэтому такая сшивка даёт ~100 %. Максимум у честных страниц по `dist/`: th 27 %, en 24 %, ru 18 %, ja/ko/zh 9 %, ar 5 %. |
| Уникальный интент: `title` и `H1` | дословный повтор запрещён; пересечение слов заголовка **≤ 0.80** | Максимум **законного** пересечения H1 в наборе — 0.71 (гео-пара «From Central Pattaya to…» ↔ «From Jomtien to…»: интент разный, заголовки обязаны быть похожи). Порог выше этой отметки и ниже уровня «отличается одним синонимом». |
| Compliance-линтер | ноль нарушений | Тот же `scripts/lib/compliance-lexicon.mjs`, что и в `check-seo`: цены, промо, рекламный регистр, медицинские обещания, «бывшее название». |

Провалила **хотя бы одну** — страница собирается, но остаётся `noindex` и вне
sitemap.

### Порядок рассмотрения

Кандидаты сортируются по `<locale>/<suffix>` и рассматриваются по одному.
Очередной сравнивается с корпусом плюс с теми кандидатами, что **уже прошли**
ворота на этом прогоне. Отклонённый в корпус не попадает: если две страницы
дублируют друг друга, отклонить надо одну, а не обе. При прочих равных
проходит лексикографически первая — это не эстетика, а гарантия, что один и тот
же коммит даёт один и тот же `sitemap.xml`.

## 5. Две ступени ОТК

**Ступень 1 — во время сборки, по данным** (`src/content-factory/registry.mjs`).
Быстрая, работает до отрисовки HTML, поэтому её результат можно использовать
для `robots` и sitemap. Видит только текст кластеров: копирайт
страниц-личностей лежит в `.ts`-модулях вёрстки и в этот момент недоступен.

**Ступень 2 — после сборки, по `dist/`** (`auditContentFactory()` в
`scripts/check-seo.mjs`). Берёт **отрисованный** основной текст страницы и
сравнивает со **всем** indexable-корпусом локали, включая написанные руками.
Функция та же — `evaluateCandidates()`, — поэтому пороги разъехаться не могут
физически.

Что здесь ошибка, а что нет:

- допущенная страница провалила ворота по `dist/` → **сборка падает**. В индекс
  уехал бы дубль или тонкая страница;
- отклонённая страница по `dist/` выглядит проходной → **не ошибка**, строка
  отчёта. Ступень 1 консервативнее, и это безопасная сторона;
- у кандидата нет собранной страницы → **сборка падает**. Отклонённая ворота́ми
  страница обязана существовать под `noindex`, а не исчезать в 404.

Проверено на живом кластере (2026-08-28):

```
# страница ru/strains/blue-dream, у которой основной текст подменён на текст хаба
SEO check failed with 1 issue(s):
- Контент-завод: ru/strains/blue-dream допущена в индекс воротами по данным,
  но провалила проверку по dist/ — borrowed-text: 45% собственного текста
  уже стоит на ru/strains при пороге 45%
```

## 6. Как добавить кластер: пошагово

1. **Напиши текст.** Не шаблон с подстановками, а текст. Если для новой
   страницы нечего сказать на 400 слов сверх того, что уже стоит на соседней, —
   страницы не должно быть. Ворота её всё равно не пропустят, а собранная
   noindex-страница пользы не приносит никому.

2. **Положи данные** в `src/data/<кластер>.ts` (или `.mjs`) по правилам из §3.

3. **Создай `src/content-factory/clusters/<кластер>.mjs`** по образцу
   `strains.mjs`: `id`, `hubSuffix`, `linkLabelKeys`, `related`, `candidates()`.
   Функция сборки собственного текста обязана повторять порядок вывода шаблона.

   На двух-трёх слагах `linkLabelKeys` и `related` пишут списком. Начиная
   примерно с десяти — **выводи их из данных**, а не перечисляй: список,
   набранный руками, расходится с набором данных при первом же пополнении и
   расходится молча. В `strains.mjs` ключ подписи считается из слага
   (`gorilla-glue-4` → `gorillaGlue4Strain`), а соседи берутся из того же поля
   `compareWith`, из которого строка «с чем сравнивать» печатается в блоке
   фактов, — поэтому перелинковка и текст страницы физически не могут
   разъехаться. Что вывод сошёлся со словарями `ui.json`, проверяет
   `npm run check:strains`.

4. **Зарегистрируй кластер** в `FACTORY_CLUSTERS` (`src/content-factory/registry.mjs`).
   Это единственная строка, которую придётся дописать руками.

5. **Добавь подписи ссылок** в `src/i18n/<locale>/ui.json` под ключами из
   `linkLabelKeys` — на всех локалях, где у кластера есть кандидаты.

6. **Сделай шаблон страницы** в `src/pages/[lang]/…`. `getStaticPaths()` берёт
   пути **из данных кластера** — не из политики индексации: иначе отклонённая
   ворота́ми страница исчезнет вместе с URL, и вместо честного noindex
   получится 404 на живой ссылке. Так сделаны все три маршрута:
   `strains/[slug].astro` (перебирает `STRAIN_PAGES` и пропускает локали без
   текста), `questions/[topic].astro` и `getting-here/[from].astro`. Из
   `getAvailableLocales()` локали берут только хабы — они ведутся вручную.

7. **Хаб кластера** (страница-список) добавляется **вручную** в
   `MANUAL_INDEX_POLICY_RULES` в `src/lib/index-policy.mjs`. Хаб один на
   кластер, он пишется руками и воротами не проверяется.

8. **Прогони проверки:**

   ```bash
   npm run check:factory     # вердикт ворот, без сборки
   npm run build
   npm run check:seo
   ```

Чего делать **не** нужно: дописывать слаги в `MANUAL_INDEX_POLICY_RULES`,
править `EXPECTED_INDEXABLE_PAGE_COUNT` (он вычисляется), добавлять слаги в
`SEO_LINK_LABEL_KEYS` и `RELATED_SUFFIXES` в `src/data/footer-seo-links.ts`
(они подмешиваются из кластера). Если что-то из этого приходится делать
руками — кластер собран не по контракту.

## 7. Что проверяет CI

`.github/workflows/main.yml`: `npm ci` → `npm run build` → `npm run check:seo`
→ `git diff --exit-code`.

Что из этого касается завода:

- **`git diff --exit-code`.** Сборка не имеет права менять рабочее дерево.
  Именно поэтому вердикт ворот — вычисление, а не файл.
- **Сходимость счётчика.** `EXPECTED_INDEXABLE_PAGE_COUNT` = ручные страницы +
  допущенные заводом; `check-seo` требует, чтобы столько же URL было в
  `sitemap.xml`, чтобы у каждого была собранная HTML-страница и чтобы у каждой
  собранной страницы `robots` совпадал с политикой. Сегодня: **124 = 90 + 34**
  (сорта 6 + вопросы 12 + гео-маршруты 16).
- **Вторая ступень ОТК** — см. §5.
- **Граф перелинковки.** У каждой indexable-страницы должна быть входящая
  контекстная ссылка на своей локали (иначе сирота) и хотя бы одна исходящая
  (иначе тупик). Для заводской страницы это обеспечивают `linkLabelKeys` и
  `related` кластера; забыл ключ подписи — сборка упадёт с «orphan».
- **Compliance-линтер** по всему `dist/`, `content-cache/` и `src/i18n/`.
- **Рукописные расстояния.** `checkHandWrittenDistances()` запрещает числа
  метров и минут ходьбы в `src/data/**`, `src/lib/**` и `content-cache/**`.
  Расстояния считает `src/lib/geo.ts` гаверсинусом. Это относится и к тексту
  кластеров: неверное расстояние хуже отсутствия страницы — человек пойдёт не
  туда.

## 8. «Моя страница noindex, что делать»

```bash
npm run check:factory
```

Он печатает по строке на кандидата и, если тот отклонён, — код и причину:

| Код | Что значит | Что делать |
| --- | --- | --- |
| `empty` | нет `title`, `H1` или текста | заполнить данные |
| `thin` | мало собственного текста | дописать по делу, а не разбавить |
| `duplicate-text` | Жаккар выше 0.20 | страница дублирует соседнюю — либо переписать, либо не заводить её вовсе |
| `borrowed-text` | больше 55 % текста уже стоит на indexable-страницах локали (суммарно, не на одной) | вынести общее в одну страницу и сослаться на неё |
| `duplicate-title` / `duplicate-h1` | заголовок дословно повторяет чужой | у страниц должен быть разный интент, а не разный URL |
| `heading-overlap` | заголовки почти совпадают | то же самое |
| `compliance` | сработал линтер | см. текст нарушения: цена, промо, рекламный регистр, неподтверждённый факт |

Отдельно: **не пройти ворота — штатный исход, а не авария.** Красной сборку это
не делает. Красной её делает только расхождение между ступенями (§5) или
сломанный граф ссылок.

### Что вердикт `index` означает, а что нет

Формулировку «ворота решают, заслуживает ли страница индекса» использовать
нельзя — она обещает больше, чем метрики умеют.

Ворота меряют **объём и лексическую новизну**, и только их. Проверено на живом
корпусе: текст `en/getting-here/big-buddha` с переставленными словами внутри
окон по четыре слова даёт против собственного оригинала Жаккар 0.00 и
заимствование 0 % — пятисловные шинглы рассыпаются от любой перестановки.
Тысяча слов уникальной бессмыслицы проходит по всем порогам. Ни то, ни другое
не реалистичная авторская ошибка, но отсюда следует главное:

- ворота **не отличают** содержательный текст от пересказа того же самого
  другими словами. Для пересказа есть отдельная ОТЧЁТНАЯ метрика (см. ниже), и
  она ничего не блокирует;
- решение «про этот ориентир нечего сказать сверх расстояния» остаётся **за
  человеком** и фиксируется записью в `GEO_ROUTE_EXCLUSIONS` с причиной —
  именно поэтому этот список существует и проверяется
  `assertGeoRouteCoverage()`.

Вердикт `index` читается так: «страница не тонкая и лексически не повторяет
соседнюю». Не «страница хорошая».

### Пересказ внутри страницы — отчёт, не ворота

`npm run check:seo` печатает долю **знаменательных слов** (длиннее трёх букв,
без стоп-слов) лида и FAQ, которые уже встречаются в разделах по H2, и
перечисляет indexable-страницы, где эта доля выше 50 %.

Метрика появилась потому, что прежняя проверка повтора (Жаккар по пятисловным
шинглам между разделами) на пересказ давала честный ноль: FAQ, повторяющий
раздел другими словами, шинглов с ним не делит. При этом пересказанные слова
идут в зачёт порога объёма, то есть страница выглядит длиннее, чем она есть.

Метрика **не блокирует сборку**: «этот вопрос добавляет факт, а этот
пересказывает раздел» — решение человека. Её работа — не дать пересказу
проехать незамеченным.

### Ворота обязаны отклонять плохое — и это проверяется

`scripts/lib/quality-gate-fixtures.mjs` — набор заведомо плохих кандидатов
(тонкий, пустой, дословная копия соседа, сшивка из трёх чужих страниц, дубль
`title`, рекламный регистр). Каждый обязан быть отклонён именно по своему коду;
прогон стоит в `npm run check:seo` и валит сборку, если хоть один прошёл.

Это нужно потому, что за три кластера ворота не отклонили ни одного кандидата
(87 из 87 допущено), и зелёный отчёт `check:factory` одинаково выглядит и когда
ворота работают, и когда они сломаны. По той же причине отчёт печатает не
только значение метрики, но и **запас до порога**: видно, является ли порог для
кого-нибудь связывающим.

## 9. Границы завода

Чего этот механизм **не** делает и делать не должен:

- **Не переводит.** Кандидат на локали — это написанный на этой локали текст.
  Машинный перевод описания сорта — ровно та тонкая страница, из-за которой
  набрались 149 отказов. В `check-seo` стоит проверка доли латиницы в прозе
  (`MAX_FOREIGN_SCRIPT_SHARE`), которая ловит наполовину переведённую страницу.
- **Не выдумывает данные.** Координаты, расстояния, свойства сортов, факты о
  законе — только из проверяемого источника. Ориентир, для которого нельзя
  обосновать координату, страницы не получает.
- **Не генерирует хабы.** Хаб пишется руками, он один на кластер.
- **Не делает страницы из `content-cache/`.** Там лежат 18 слагов-сирот (126
  файлов) с машинным текстом; их нельзя подключать без полного переписывания.

## 10. Честный путь к сотням страниц

Сотни страниц — это **не** сотни тем. Это:

1. **Уникальность на данных, а не на переформулировках.** Вычисленный маршрут
   (`describeLandmarkWalk()` считает расстояние гаверсинусом), реальные свойства
   сорта, конкретный ответ на конкретный вопрос. Данные дают уникальность,
   которую ворота видят; синонимы — не дают.
2. **Умножение на локали там, где выдача пуста.** По разведке японская,
   корейская, китайская и арабская выдача по каннабису в Паттайе практически
   свободна. Сейчас кластер сортов существует только на en+ru: пять локалей
   ждут не генератора, а написанного носителем текста.

Между этими двумя пунктами и порогом в 400 слов помещается ровно столько
страниц, сколько кто-то готов написать. Ворота не создают контент — они не дают
опубликовать то, чего нет.

## 11. Кластер `getting-here/*`: уникальность, которая начинается с числа

Третий кластер устроен иначе, чем два первых, и стоит объяснить, чем именно.

**Число не пишется, а считается.** Строку «столько-то от ориентира, столько-то
пешком» печатает `describeLandmarkWalk(slug, locale)` — гаверсинус между пином
магазина и координатой ориентира, время диапазоном (прямая всегда короче
улиц) и без времени вовсе, если идти пешком уже нереально. В данных кластера
цифр расстояния и минут нет ни одной; за этим следит блокирующая
`checkHandWrittenDistances()`. Обещание «пять минут пешком» до точки, до
которой идти вдвое дольше, возвращается однозвёздочным отзывом — это и есть
причина всей конструкции.

**Данных два набора, и оба обязательны.** `src/data/landmarks.ts` даёт
координату с источниками и фактуру маршрута (чем едут, где пересадка, что
видно по пути, где ошибаются поворотом, чем день отличается от вечера);
`src/data/geo-routes.ts` — авторские разделы, лид, происхождение координаты и
вопросы. Локаль, у которой есть только один из наборов, страницы не получает:
`getStaticPaths()` проверяет оба.

**Отказ записывается словами.** `GEO_ROUTE_EXCLUSIONS` перечисляет ориентиры,
которым страница не заводится, и причину каждого: четыре уже описаны
написанными руками страницами районов, а `beach-road` — тот случай, ради
которого правило и существует: его принятая точка совпадает с углом Walking
Street, и сверх расстояния он не сказал бы ничего.
`assertGeoRouteCoverage()` падает на сборке, если ориентир из `LANDMARKS` не
получил ни страницы, ни записанного отказа: молчаливое «страницы нет»
неотличимо от «страницу забыли».

**Хаб — `locations`.** Он написан руками и перечисляет маршруты списком, но
руками там задана только строка: попадёт ли ссылка на страницу, решает
`getIndexPolicy`, то есть ворота. Не прошедший ворота маршрут исчезает из хаба
сам и остаётся живым URL под `noindex, follow`.

## 12. Умножение на локали: th / ar / zh / ko / ja

Второй множитель из §10 — не «ещё сто тем», а те же сильные страницы на
локалях, где выдача пуста. Разведка: японский запрос про каннабис в Паттайе
держат личные блоги, китайский — тайваньские тревел-сайты, корейский — новости
о задержаниях, арабский — Airbnb и подборки жилья. Ни одного диспенсари Паттайи
ни в одной из четырёх. Маршрут, шаблон, разметка, перелинковка и ворота уже
работают на всех семи локалях, поэтому стоимость входа — только текст.

**Это не перевод, и это проверяет машина.** Ворота считают похожесть ВНУТРИ
локали: посимвольными 10-граммами для th/zh/ja/ko и 5-словными шинглами для ar
(`CHAR_NGRAM_LOCALES` в `scripts/lib/text-similarity.mjs`). Один шаблон,
прогнанный через переводчик на пять языков, даёт внутри каждой локали
одинаковый скелет предложений и валит и Жаккар, и коэффициент включения.
Поэтому у каждой локали СВОЙ набор разделов, а не свой перевод одного набора:

| локаль | ось, вокруг которой построен текст |
| --- | --- |
| ja | имя сорта — не спецификация; японская выдача состоит из отчётов об одной партии |
| ko | у названий нет правообладателя, поэтому «оригинала» не существует; выдача — новости о происшествиях |
| zh | в меню только английские слова, и читатель не знает, что они буквально значат |
| th | читатель местный: вопрос не «что это», а почему ярлыки английские и насколько им верить |
| ar | правовой контекст дома закрыт; страница объясняет и прямо говорит, что не призывает покупать |

Замер после раскатки (`npm run check:factory`, вторая ступень по `dist/`):
объём th 4033–4125 симв. при пороге 2500, zh 1566–1698 при 1050, ko 1960–2035
при 1300, ja 2208–2344 при 1450, ar 697–780 слов при 640; похожесть внутри
локали 0.00–0.06 при пороге 0.20, кумулятивное заимствование 5–9 % при пороге
55 %.

**Порог объёма для CJK считается в символах, а не в словах**, и коэффициенты в
`MIN_OWN_CHARS` посчитаны по этому сайту, а не взяты из таблицы — см. комментарий
в `scripts/lib/quality-gate.mjs`. Проверять новый текст словами бессмысленно:
в th/zh/ja/ko слова не разделены пробелами.

**Оговорка о языке, которую нельзя снимать молча.** Носителя ни одного из пяти
языков в проекте нет. Текст написан по терминологии, уже стоящей на этих
локалях (`legal-guide.ts`, `about-copy.ts`), и проходит compliance-лексикон на
всех семи языках, но живой вычитки носителем не проходил. Наибольший риск, в
порядке убывания: тайский (регистр и связки — самая длинная проза набора),
арабский (падежные окончания и порядок слов в длинных периодах), корейский
(уровни вежливости в FAQ), японский и китайский (риск ниже: короче предложения
и жёстче терминология). Это записано в шапках
`src/data/strain-pages-open-locales.ts` и
`src/data/guide-choosing-flower-open-locales.ts` и обязано быть снято правкой
человека, а не молчанием.

**Редирект не имеет права перекрывать indexable-страницу.** Раскатка на пять
локалей потребовала снять из `vercel.json` три пары 301, которые вели
`/:lang(th|ar|zh|ko|ja)/strains/*` и `.../guides/choosing-flower-pattaya` на
посторонние разделы. Редирект на границе сети срабатывает раньше статического
файла, поэтому оставить их значило бы объявить страницу в sitemap и hreflang и
отдавать по ней 301. Проверка `validateRedirectShadowing()` в
`scripts/check-seo.mjs` теперь блокирует такое состояние. Она же нашла уже
существовавший дефект: список legacy-слагов сортов закрывал 301-м семь слагов,
у которых давно появились написанные страницы, — четырнадцать indexable URL на
en и ru, которые прод отдавать не мог.
