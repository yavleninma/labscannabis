**Задача:** W1-08 из [`PLAN-CONVERSION-2026-08.md`](./PLAN-CONVERSION-2026-08.md).
**Дата:** 2026-08-27.
**Правило:** этот файл — единственный источник истины по именам событий. Новое имя события
не заводится без правки этого файла и [`src/lib/analytics.ts`](../../src/lib/analytics.ts).

## 0. Что было сломано

| Что | Где было | Следствие |
|---|---|---|
| `window.va?.("event", name, payload)` | `src/components/TrackingScript.astro` | Vercel Analytics ожидает `va('event', { name, data })`. Со строкой вместо объекта **не писалось ни одно событие** — конверсию нельзя было измерить в принципе |
| `payload` из 8–14 ключей | там же | Vercel хранит максимум **два** ключа данных на событие, остальное молча отбрасывается |
| `window.dataLayer.push(...)`, `window.gtag?.(...)` | там же | ни GTM, ни GA4 на сайте не подключены — вызовы уходили в никуда |
| шесть имён одного действия: `hero_whatsapp_click`, `location_whatsapp_click`, `contact_whatsapp_click`, `contact_messenger_click`, `map_open_click`, `contact_call_click` | вся разметка | отчёт «страница → контакт» приходилось склеивать руками, а каналы LINE/Telegram/телефон терялись в общей куче |
| эвристика `getWhatsAppSource` / `readCtaUtm` по восьми `data-*` синонимам, пути и рефереру | там же | источник **угадывался**, хотя разметка могла назвать его явно |

## 1. События

Событий ровно два, и различаются они смыслом, а не каналом.

| Событие | Смысл | Считается конверсией |
|---|---|---|
| `contact_click` | человек ушёл в контакт: мессенджер, телефон, карточка в Google Maps, маршрут | **да** — это единственная метрика владельца |
| `nav_click` | человек перешёл внутри сайта: меню, переключатель языка, тематическая ссылка | нет |

## 2. Разметка

Контракт держится на трёх `data-*` атрибутах якоря. Никаких других tracking-атрибутов
в разметке быть не должно — `data-track-detail`, `data-wa-source`, `data-whatsapp-ref`,
`data-utm-*` удалены и не возвращаются.

```html
<!-- целевое действие -->
<a href="…" data-track="contact_click" data-channel="whatsapp" data-placement="sticky">…</a>

<!-- переход внутри сайта -->
<a href="…" data-track="nav_click" data-placement="header" data-target="contact">…</a>
```

### `data-channel` — куда ушёл человек

| Значение | Что за ссылка |
|---|---|
| `whatsapp` | `wa.me/…` |
| `line` | `CONTACT.line`, рендерится только при `CONTACT.lineEnabled` |
| `telegram` | `CONTACT.telegram`, рендерится только при `CONTACT.telegramEnabled` |
| `phone` | `tel:` |
| `maps` | **карточка** в Google Maps — `getMapsSearchUrl()` / `GOOGLE.listingUrl` (`maps?cid=…`) |
| `directions` | **маршрут** — `getMapsDirectionsUrl()` (`maps/dir/?api=1&destination=…`) |

`maps` и `directions` разделены сознательно. Клик по карточке — «пошёл читать отзывы»,
клик по маршруту — «встал и пошёл к двери». Это разные целевые действия с разной
стоимостью, и в одну цифру их складывать нельзя.

### `data-placement` — откуда нажали

`header`, `hero`, `home`, `sticky`, `rail`, `footer`, `map_block`, `legal_guide`,
`area`, `delivery`, `seo`, `contact`, `locations`, `retired`, `reviews`, `language`.

Значения `product_card` в списке нет и не будет: витрины на сайте нет по железному
правилу «никакой корзины и никакого прайса». Нормализатор в `TrackingScript.astro`
свалил бы такое место в `other`, и потеря была бы не видна в отчёте.

Список объявлен в `TRACK_PLACEMENTS` (`src/lib/analytics.ts`). `ContactRail.astro`
принимает место пропом `placement` и типизирован `TrackPlacement`, поэтому опечатку
в странице видно на этапе типов, а не в отчёте через месяц.

### `data-target` — только у `nav_click`

Слаг или ключ пункта меню (`contact`, `labs-dispensary-pattaya`, `delivery/pattaya`,
код языка). Обрезается до 64 символов.

## 3. Что уходит в счётчики

Один делегированный слушатель на весь документ
([`src/components/TrackingScript.astro`](../../src/components/TrackingScript.astro)):
**один клик — одно событие**, без дублей от вложенных обработчиков.

```js
// Vercel Web Analytics — строго объект и не более двух ключей данных
window.va?.("event", { name: "contact_click", data: { channel: "whatsapp", placement: "sticky" } });

// Яндекс.Метрика — цель только на контакт, переходы внутри сайта целью не считаются
window.ym?.(YM_ID, "reachGoal", "contact_whatsapp");
```

Неизвестное значение `data-channel` / `data-placement` не выдумывается и не
пробрасывается как есть — оно нормализуется в `other` (`TRACK_FALLBACK`). Отчёт
остаётся читаемым, а мусорное значение сразу видно как отдельную строку.

## 4. Счётчики

| Счётчик | Что считает | Как включается |
|---|---|---|
| Vercel Web Analytics | просмотры страниц | `astro.config.mjs` → `vercel({ webAnalytics: { enabled: true } })`, стаб `window.va` вставляет адаптер |
| Яндекс.Метрика | визиты и **цели** | `src/components/Analytics.astro`, ID из `PUBLIC_YM_ID` |

**Vercel считается счётчиком просмотров, не целей.** Кастомные события требуют платного
плана, на Hobby они молча не пишутся (O-09) — строить конверсию на них нельзя, пока тариф
не подтверждён владельцем. Основной счётчик целей — Метрика: она бесплатна, а
русскоязычная доля трафика Паттайи в ней видна лучше, чем где-либо ещё.

### Включение Метрики — блокирующий пункт приёмки волны

Пока `PUBLIC_YM_ID` не проставлен в переменных окружения Vercel, целей не пишется
**ни одной**: кастомные события Vercel на тарифе Hobby молча не сохраняются (O-09),
а Метрика при пустой переменной не рендерится вообще — в `dist/en/index.html` ноль
вхождений `mc.yandex.ru` и ноль вызовов `ym(`. Контракт событий при этом корректен,
но пункт DoD «в Метрике за сутки фиксируются цели по 5 каналам» в день деплоя
невыполним.

Поэтому шаги ниже — не раздел «когда-нибудь», а пункт приёмки волны рядом с O-01 и
O-02. До его выполнения деплой имеет смысл как правка воронки, но не как измерение.

1. Завести счётчик (домен `labscannabis.boutique`); верификация Вебмастера уже стоит
   метой `yandex-verification` в `PageLayout.astro`.
2. Положить номер в переменную окружения проекта Vercel: `PUBLIC_YM_ID=<номер>`.
3. Пересобрать. Переменной нет или значение не число — `Analytics.astro` **не рендерит
   ничего**: сайт работает ровно как раньше, ошибок в консоли нет.

### Цели в интерфейсе Метрики

Тип цели — «JavaScript-событие», идентификатор:

| Цель | Действие |
|---|---|
| `contact_whatsapp` | ушёл в WhatsApp |
| `contact_line` | ушёл в LINE |
| `contact_telegram` | ушёл в Telegram |
| `contact_phone` | нажал на телефон |
| `contact_maps` | открыл карточку в Google Maps |
| `contact_directions` | построил маршрут |

`contact_line` и `contact_telegram` до подъёма флагов `lineEnabled` / `telegramEnabled`
(O-02) не сработают ни разу — кнопок в разметке нет. Цели заводить всё равно стоит
заранее, чтобы в день включения канала не потерять первые сутки.

### ⚠️ Чего в Метрике включать нельзя

**Вебвизор, запись сессий и карта кликов выключены и включаться не должны.** В Таиланде
действует PDPA, посетители приезжают из семи стран, а сайт — про контролируемое
вещество. Запись поведения посетителя здесь несопоставима по риску с пользой.
В `Analytics.astro` это зафиксировано явно: `webvisor: false`, `clickmap: false`.
Решение про cookie-баннер — за владельцем (O-11).

## 5. Чего в событиях нет и почему

- **UTM и источник визита.** Не помещаются в два ключа данных Vercel, а Метрика
  разбирает `utm_*` сама. Прежняя атрибуция в `sessionStorage` (`labs_attribution`)
  кормила только выброшенный payload и удалена вместе с ним.
- **Текст кнопки и путь страницы в `detail`.** Путь счётчик знает и так, текст кнопки
  меняется от локали к локали и ломает сведение отчёта.
- **Ничего в теле сообщения WhatsApp.** Технический тег `[source: …; page: …; utm: …]`
  дописывался в префилл и был виден человеку в его мессенджере до отправки — убран
  в W1-04 и не возвращается ни под каким предлогом. Ручная атрибуция, если понадобится,
  делается невидимым суффиксом из 2–4 символов, см. `docs/growth/cta-codes.md`.

## 6. Проверка

```bash
# имён событий не больше трёх
grep -rhoP 'data-track="\K[^"]+' src/ | sort -u

# каналы и места — только из словаря src/lib/analytics.ts
grep -rhoP 'data-channel="\K[^"]+' src/ | sort -u
grep -rhoP 'data-placement="\K[^"]+' src/ | sort -u

# старые атрибуты не вернулись
grep -rn 'data-track-placement\|data-track-detail\|data-wa-source\|data-utm-' src/
```

В браузере: клик по кнопке WhatsApp в sticky-панели даёт **ровно один** вызов
`va('event', {name:'contact_click', data:{channel:'whatsapp', placement:'sticky'}})`
и, при поднятом `PUBLIC_YM_ID`, ровно один `ym(ID, 'reachGoal', 'contact_whatsapp')`.
